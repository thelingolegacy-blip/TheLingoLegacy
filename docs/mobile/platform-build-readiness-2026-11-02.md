**Snapshot date:** 2026-11-02  
**Branch:** `recovery/platform-ops-preview-2026-11-02`  
**Status:** NOT RELEASE READY — source inspection only; no Flutter/Gradle/Xcode build is claimed.

## Verified source findings

| Area | Observed source state | Consequence |
|---|---|---|
| Firebase Hosting | `firebase.json` publishes only `build/web` | Safer publication boundary; a Flutter web build must exist before deployment. |
| Firebase Flutter options | `lib/firebase_options.dart` contains `YOUR_*_API_KEY`, `YOUR_*_APP_ID`, and a project ID placeholder target | Firebase initialization cannot be treated as configured or integration-tested. Obtain project-issued options through authorized Firebase project access. |
| Android Firebase | `android/app/google-services.json` was not present at the inspected branch path | Android Firebase app registration/configuration is incomplete. |
| Android release signing | `android/app/build.gradle` assigns `signingConfigs.debug` to the release build type | Release signing is not acceptable for store publication. Do not ship a debug-signed release. |
| iOS project | `ios/Runner.xcodeproj/project.pbxproj` was absent; `project.pbxproj.stub` contains only a stub comment | No valid Xcode project is available at the expected path; iOS archive/signing cannot be certified. |
| Flutter dependencies | `pubspec.yaml` declares Flutter, Firebase Core/Auth/Database/Storage/Analytics, Provider, HTTP, localization, preferences, connectivity, tests and assets | Dependency resolution, asset completeness, plugin compatibility and platform builds remain unverified. |

## Required remediation sequence

1. **Firebase project owner:** verify the intended Firebase project, register each real platform app, and generate platform-specific FlutterFire configuration. Never substitute invented API keys, app IDs, sender IDs, or bundle IDs.
2. **Android:** add the provider-issued `google-services.json`; verify the Gradle plugin and wrapper versions; provision a production signing key through an approved secret-management process; ensure release builds fail closed when signing inputs are absent; keep signing material out of Git and build logs.
3. **iOS:** generate/restore a complete Xcode project and plugin registrant using the pinned Flutter toolchain; verify the bundle identifier against the Apple Developer account; configure signing through account-authorized credentials, not committed certificates or profiles.
4. **Build matrix:** run dependency resolution, static analysis, unit tests, Android debug build, Android release-signing validation, iOS simulator build, iOS archive validation on macOS, and Flutter web build.
5. **Firebase Hosting:** confirm `build/web` is generated by the same tested commit; deploy only after artifact inspection and explicit staging acceptance.
6. **Release evidence:** retain commit SHA, toolchain versions, dependency lockfile, test results, artifact checksums, signing identity metadata (never private keys), and independent reviewer verdict.
