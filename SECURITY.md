# Security Policy

## Supported versions

Security fixes are prioritized for the current default branch and the currently supported production release, once a release is independently verified. Older snapshots and unreleased branches may not receive fixes.

## Reporting a vulnerability

**Do not disclose suspected vulnerabilities in a public issue, pull request, discussion, or commit.**

Use GitHub's **Report a vulnerability** action in the repository Security tab when private vulnerability reporting is enabled. If that option is unavailable, contact the repository maintainers through an established private channel and request a confidential security-reporting route. Do not include exploit details, personal data, credentials, access tokens, private keys, or customer records in public communications.

Please include, where safe:
- affected component, file path, version or commit;
- impact and realistic attack preconditions;
- minimal reproduction steps or a non-destructive proof of concept;
- suggested mitigation, if known.

Do not access, modify, delete, or exfiltrate another person's data; do not disrupt services; and do not perform testing against production systems without explicit written authorization.

## Response and remediation

The maintainers should acknowledge a private report, triage severity and scope, assign an owner, track remediation privately, and coordinate disclosure after a fix or mitigation is available. No response-time or remediation SLA is claimed until an owner and support process are formally assigned.

## Scope and limitations

This policy does not imply that a security team, 24/7 monitoring, bug bounty, endpoint antivirus/EDR, penetration testing, or production incident-response capability is currently staffed or active. Those capabilities require separate evidence and acceptance.

For urgent exposure involving credentials or personal data, do not paste the material into an issue or chat. Notify an authorized repository owner privately so credentials can be revoked and affected data contained through the approved provider controls.
