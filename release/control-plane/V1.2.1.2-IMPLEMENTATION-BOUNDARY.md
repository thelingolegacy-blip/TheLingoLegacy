## Authority Model

The existing release evidence generators remain artifact/evidence producers. They do not become the authoritative certification authority.

Authoritative promotion requires server-side state backed by D1:

1. `app_registry_v1_2_1`
2. `release_evidence_ledger_v1_2_1`
3. `certification_decisions`
4. `deployment_state_events`

Certification must resolve candidate identity from trusted release evidence and runtime deployment identity. Client-supplied PASS/VERIFIED/LIVE claims are not authoritative.
